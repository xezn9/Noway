# ApkBuilderApp (v2 — عبر Termux)

بعد ما تبين إن تنفيذ أدوات منزّلة وقت التشغيل داخل filesDir **ممنوع من أندرويد 10+** (noexec)،
وإن بنايات JDK/SDK العادية مبنية لـ glibc وما تشتغل على Bionic (مكتبة C تبع أندرويد) حتى
لو حليت مشكلة الصلاحيات — تم تغيير التصميم: **التطبيق صار واجهة بس**، والبناء الفعلي
يصير داخل **Termux** (تطبيق منفصل عنده بيئة متوافقة فعلياً مع أندرويد وحزم مبنية خصيصاً لها).

## ليش Termux تحديداً؟
Termux عنده حزمه الخاصة لـ `openjdk-17/21`, `aapt2`, `d8`, `apksigner` — مبنية ومُختبرة
للعمل مباشرة على Bionic/aarch64. هذا يحل المشكلتين دفعة وحدة بدون أي هندسة إضافية منّا.

## إعداد الجهاز (مرة وحدة، يسويها المستخدم قبل أول استخدام)

1. **نزّل Termux من F-Droid** (مو من Google Play — نسختهم قديمة وتوقف تحديثها):
   https://f-droid.org/packages/com.termux/

2. **فعّل السماح لتطبيقات خارجية** تستدعي Termux:
   افتح Termux وسوي:
   ```bash
   mkdir -p ~/.termux
   echo "allow-external-apps=true" >> ~/.termux/termux.properties
   termux-reload-settings
   ```

3. **نصّب الحزم المطلوبة مرة وحدة** (تطبيقنا يحاول يسويها تلقائياً أول تشغيل، لكن أسرع
   لو سويتها انت يدوياً مرة وحدة):
   ```bash
   pkg update && pkg upgrade
   pkg install openjdk-17 openjdk-21 aapt2 d8 apksigner zip
   ```

4. **android.jar**: Termux ما يوفره تلقائياً بكل الحالات. لو ظهر تحذير "android.jar غير موجود"
   بالسجل، حط نسخة منه يدوياً بـ `$PREFIX/share/java/android.jar` (تقدر تاخذها من أي
   تنصيب Android SDK عادي، أو تنزلها من مستودعات معروفة لـ `android.jar` حسب الـ API المطلوب).

5. **بتطبيقنا نفسه**: أول مرة يطلب صلاحية "الوصول لكل الملفات" (All Files Access) — هذي
   ضرورية عشان Termux يقدر يوصل نفس مجلد المشروع اللي نحطه فيه (كل تطبيق أندرويد معزول
   عن غيره افتراضياً، فنحتاج مجلد تخزين مشترك فعلي).

## كيف يشتغل الآن (داخلياً)

1. تختار ملف zip → ينسخ لمجلد `cacheDir` الخاص فينا.
2. تضغط "ابدأ البناء" →
   - ينسخ سكربت `build_in_termux.sh` (من `assets/`) لمجلد مشترك: `/sdcard/ApkBuilderApp/`
   - يفك ضغط مشروعك بنفس المجلد المشترك
   - يحلل متطلبات المشروع (نسخة Java المطلوبة من `build.gradle`)
   - يرسل Intent لـ Termux (`com.termux.RUN_COMMAND`) يشغل السكربت بالخلفية
   - السكربت (داخل Termux) يصرّف الكود، يحوله dex، يعبّي الموارد، يوقع — ويكتب
     `build.log` (سجل حي) و`build.done` (علامة انتهاء) بنفس المجلد المشترك
   - تطبيقنا يراقب هذين الملفين كل 1.5 ثانية ويعرض السجل حي بالواجهة
3. لما يخلص (`build.done` يحتوي `DONE:0`) → زر "حفظ APK" يصير فعّال.

## الملفات المهمة
- `assets/build_in_termux.sh`       — السكربت الفعلي اللي يشتغل داخل Termux
- `TermuxBuilder.kt`                — يتحقق Termux مثبت، يرسل أمر RUN_COMMAND
- `MainActivity.kt`                 — الواجهة، نسخ الملفات للمجلد المشترك، مراقبة النتيجة
- `ProjectUnzipper.kt`              — فك ضغط آمن (حماية Zip Slip)
- `ProjectRequirementsDetector.kt`  — يقرأ build.gradle ويطلع نسخة Java المطلوبة

تم حذف `ToolchainManager.kt` و`ProjectBuilder.kt` القديمين لأنهم مبنيين على فرضية
"ننزل وننفذ الأدوات بنفسنا" اللي تبين إنها غير ممكنة تقنياً على أندرويد الحديث.

## محدودية لازم تعرفها
- أول بناء بطيء (تنصيب حزم Termux لأول مرة، خصوصاً JDK).
- المستخدم لازم يكون مثبت Termux ومفعّل `allow-external-apps` يدوياً مرة وحدة — ما نقدر
  نؤتمت هذي الخطوة لأسباب أمنية (Termux نفسه يفرضها).
- `android.jar` ما يجي تلقائياً مع حزم Termux بكل الحالات — قد تحتاج تحطه يدوياً أول مرة.
- هذا التصميم يدعم مشاريع "بسيطة" (src/res/AndroidManifest.xml بدون Gradle). مشروع Gradle
  كامل فيه gradlew يحتاج تعديل إضافي بالسكربت يشغل `./gradlew assembleDebug` بدل الخطوات
  اليدوية — أخبرني إذا تحتاجها وأضيفها.

## التوقيع ورفع رقم الإصدار (لنشر تحديثات لهذا التطبيق نفسه)

تم توليد **مفتاح توقيع دائم مخصص** بـ `keystore/apkbuilder-release.jks` (صالح 10000 يوم).
`app/build.gradle.kts` يستخدمه تلقائياً بكل بناء release — ما يحتاج أي إعداد إضافي، كل
نسخة توقّع بنفس المفتاح فتنصب كـ"تحديث" فوق القديمة مباشرة.

**⚠️ مهم جداً:**
- **احتفظ بملف `apkbuilder-release.jks` بمكان آمن خارج أي مستودع عام.** لو ضاع أو
  استخدمت مفتاح مختلف بالمستقبل، ما راح تقدر تحدّث أي نسخة ناس نصبوا التطبيق القديم —
  لازم ينزّلوه من جديد وكأنه تطبيق ثاني كلياً.
- كلمة المرور حالياً مكتوبة مباشرة بـ `build.gradle.kts` كقيمة افتراضية (`ApkBuilder#2025Secure`)
  عشان البناء يشتغل مباشرة بدون إعداد. **لو المستودع عام (public) على GitHub، غيّر هذا**
  — انقل الـ keystore والباسورد لأسرار GitHub Actions (`KEYSTORE_PATH`, `KEYSTORE_PASSWORD`,
  `KEY_ALIAS`, `KEY_PASSWORD` كمتغيرات بيئة، نفس الكود يقرأها تلقائياً لو وجدها قبل القيم
  الافتراضية) ولا تسوي commit لملف `.jks` نفسه.
- زيادة `versionCode` بكل إصدار (الحين 3) لسا مطلوبة يدوياً بكل مرة.
